# СК — Студенческий кабинет

**Живой прототип цифрового деканата.** Это не макет и не картинка: кабинет открывается по ссылке, и в нём можно пройти весь путь — войти, посмотреть расписание и оценки, подать заявку и увидеть, как меняется её статус.

> ## 🔗 Демо для жюри
> **https://129.101.103.152.sslip.io**
>
> Концепт для конкурса «Цифровой деканат будущего». Не является официальным сервисом вуза. Все данные вымышленные.

«СК» собирает в одном месте всё, что нужно студенту каждый день: расписание и дедлайны, оценки и зачётку, заказ справок и загрузку работ, новости, достижения и ИИ-помощника, который отвечает по учебным документам. А ещё здесь есть настоящие кабинеты для **старосты группы** и **сотрудника деканата** — с реальными действиями, а не заглушками.

Прототип работает на телефоне (от 360 px), открывается из России без VPN и подготовлен так, чтобы жюри могло проверить ключевые сценарии за пару минут.

## 🚀 Что попробовать за 3 минуты

1. **Студент** — войдите как `ivanov / student1`, кликните на своё имя в правом верхнем углу → откроется **карточка студента** (ФИО, курс, группа, факультет, направление).
2. **Заявка и статус** — «Документы» → закажите справку и найдите её в истории. Когда сотрудник загрузит готовый файл, рядом появится кнопка **«Скачать»**.
3. **Помощник по документам** — откройте «Помощник» и спросите, например, «Как пересдать экзамен?» или «Что будет за пропуски?». Ответ придёт **цитатой из нужного документа** со ссылкой на источник.
4. **Сотрудник** — войдите как `lebedeva / staff1`: раздел **«Заявки»** (сменить статус «В работе»/«Готово», загрузить готовый PDF) и **«Расписание»** (заменить преподавателя из пула, отменить пару).
5. **Староста** — войдите как `vetrova / student2`: раздел **«Староста»** — отметить посещаемость 20 одногруппников и отправить дедлайн или сообщение всей группе. Затем войдите как `ivanov` и убедитесь, что дедлайн появился в календаре, а сообщение — в уведомлениях.

## ✨ Возможности

### Кабинет студента
- **Вход** по логину и паролю, безопасная сессия.
- **Профиль** — карточка студента; открывается по клику на имя или аватар в шапке.
- **Главная** — расписание на сегодня, последние новости, успеваемость, заметки.
- **Календарь** — неделя с занятиями по времени, переключение недель, дедлайны. Отменённые пары помечаются явно.
- **Успеваемость** — журнал с баллами, выбор семестра и диапазона дат, посещаемость.
- **Зачётная книжка** — итоги по прошлым семестрам.
- **Документы** — заказ справок и выписок, загрузка работ (PDF/DOCX/JPG/PNG), история заявок со статусами и скачиванием готовых справок.
- **Учебные документы** — 6 типовых документов (учебный план, программа, график, приказы, положение об аттестации, правила распорядка): полный текст и **PDF**.
- **Помощник** — чат, который отвечает **по учебным документам** (цитата + ссылка на источник) и подсказывает по разделам кабинета; история за 7 дней.
- **Новости** — карточки с кратким описанием и полным текстом.
- **Достижения** — награды с прогрессом.
- **Уведомления** — лента событий с отметкой о прочтении.

### Кабинет старосты (для Ветровой)
- **Посещаемость** — список 20 одногруппников с отметками «Был / Не был», выбор даты и дисциплины, сохранение.
- **Рассылка** — дедлайн (название, дата, время) или текстовое сообщение **всей группе**. Дедлайн попадает в календарь, сообщение — в уведомления.

### Кабинет сотрудника деканата
- **Заявки** — справки и выписки из приказа: статусы «В работе» / «Готово» и загрузка готового PDF для студента.
- **Расписание** — замена преподавателя из пула и отмена пары для выбранной группы и дня.

### Общее
- **Поиск по разделам** в шапке: введите название — и перейдите на нужный экран.
- **Мобильная версия** — все основные сценарии работают от **360 px** (нижняя навигация + меню-гамбургер).

## 🧱 Технологический стек

- **Next.js 16** (App Router, JavaScript) + **React 19**.
- **SQLite** через встроенный `node:sqlite` (без внешней СУБД).
- Аутентификация: **scrypt** + соль, httpOnly-сессии.
- Деплой: **Docker** + **Caddy** (авто-HTTPS).
- Шрифт **Inter**, иконки — Material Symbols.

> SQLite выбран для прототипа (простота и нулевая настройка). Слой доступа к данным изолирован
> в `lib/db.js`, чтобы заменить БД на PostgreSQL без переписывания страниц при росте нагрузки.

## 🛠 Запуск локально

Требуется **Node.js 24+** (в нём доступен `node:sqlite` без флагов).

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

База создаётся и заполняется вымышленными данными автоматически при первом запуске:

- `.data/app.db` — SQLite-база;
- `.data/uploads/` — загруженные студентами файлы;
- `.data/results/` — готовые справки, загруженные сотрудником.

При изменении схемы или сидов удалите `.data/app.db` и перезапустите сервер.

### Скрипты

```bash
npm run dev      # разработка (Turbopack)
npm run build    # production-сборка
npm run start    # запуск production-сборки
```

## 🚢 Деплой

Пошаговая инструкция — в [DEPLOY.md](./DEPLOY.md).

Кратко: Docker Compose поднимает приложение и Caddy, база и файлы хранятся в volume `app_data`.
HTTPS выдаётся автоматически (Let's Encrypt). Домен задаётся в `.env` (`DOMAIN=...`).
На сервере настроены **fail2ban**, автообновления безопасности и **ежедневный бэкап** базы.

## 📄 Документы и помощник

Учебные документы — единый источник данных `lib/study-docs.js`. Из него:
- строится раздел «Документы → Учёба»;
- генерируются PDF (`scripts/generate-docs.mjs` → `public/docs/`);
- помощник отвечает на вопросы (`lib/docbot.js`).

Помощник **не использует LLM и внешние API**: он находит наиболее подходящий раздел документа
по ключевым словам и синонимам и возвращает короткую цитату со ссылкой «Открыть документ».
Если совпадения нет — срабатывают подсказки по разделам кабинета. Это бесплатно, работает
без VPN и всегда даёт проверяемый ответ со ссылкой на источник.

## 🔒 Безопасность

- Пароли хранятся только в виде **scrypt-хэша с солью**, сравнение — `timingSafeEqual`.
- Сессия — случайный 32-байтный токен в **httpOnly** cookie (`sameSite=lax`, `secure` в проде).
  В базе хранится только **SHA-256 хэш токена** — при утечке БД сессии не переиспользовать.
- **Rate limiting** на вход: не более 30 попыток за 5 минут с одного IP.
- **CSRF-защита**: проверка `Origin` на всех изменяющих запросах + `SameSite=lax`.
- **Security-заголовки**: `Content-Security-Policy`, `Strict-Transport-Security`,
  `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- Все данные и API **скоупятся по `user.id`**: студент не может открыть чужие оценки, заявки,
  заметки или скачать чужую справку; действия старосты и сотрудника проверяются по роли.
- Лимиты длины полей и ранний отказ по размеру загрузки (защита от «тяжёлых» запросов).
- Загруженные файлы и готовые справки лежат вне `public/` и отдаются только через проверяемый эндпоинт.
- В коде нет ключей и паролей сервисов; `.env`, `.data`, `*.db` исключены из репозитория.
- На сервере: **fail2ban** (защита SSH от перебора), автообновления безопасности,
  **ежедневный бэкап** SQLite-базы (хранится 14 дней).
